## Original Feedback
> A server error occurred.

Submitted 2026-11-10 17:39 UTC by a steward, right after attaching the October and November Hetzner
invoices to the wiki billing page.

## Error Context
`POST /api/v1/admin/cost/invoices/scan` → `504: Request failed with status code 504`.

Backend logs from the same minute (17:37 and 17:38) show two scans, both ending
`Invoice scan: 0 ingested, 31 unreadable, 0 already known`, with two kinds of per-PDF error:

- `null value in column "id" of relation "vendor_invoices" violates not-null constraint` for every PDF
  that was read
- `Key not found` for attachments whose file is no longer in the wiki bucket

## Analysis

**The 504.** The scan ran inside the HTTP request and OCR'd 31 PDFs one after another (about 5 s
each), well past the reverse proxy's timeout.

**Why nothing was ever stored.** `InvoiceIngestService` wrote rows with `repository.insert({...})`.
TypeORM does not run entity listeners for a plain object, so `VendorInvoice`'s `@BeforeInsert` never
set the `id`. That broke both the success insert and the failure insert. The failure insert swallowed
its own error, so no row of any kind was written, and every later scan (webhook, daily job, button)
paid for OCR of all 31 PDFs again.

**Duplicates and deleted uploads.** The 31 attachments are about 8 distinct Hetzner bills, attached
more than once. Some of the copies were since removed from the page, which leaves an Outline
attachment row with no S3 object behind it. Once the id bug was fixed, the duplicates would have
counted the same month twice.

## Fix

- Give the id explicitly in both inserts.
- Count a missing S3 object as skipped, not as a failure for a steward to fix.
- Read each file name only once. Duplicate attachments are skipped before download and OCR, and a
  deleted copy falls through to a live one.
- The scan button queues the existing `invoice-scan` job and returns 202. The scan writes its progress
  to Redis (`cost:invoice-scan`), and the page polls `GET /admin/cost/invoices/scan-status`.
- Steward page: the scan control moves to the top, under the vendor table. It says which vendors one
  scan covers, links to the billing page itself, shows a progress bar and the last-scan result, and
  marks vendors whose last invoice is over 40 days old, with a link to that vendor's billing page.
- None of Hetzner, Mistral, Resend or Backblaze has an invoice API, so the PDF upload stays manual
  (decided 2026-11-10). Email intake would be a separate item.
